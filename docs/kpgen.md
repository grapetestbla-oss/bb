# KPGen — генератор коммерческих предложений

Микро-SaaS внутри этого репозитория: отдельный продукт с собственными
пользователями, подписками и приёмом оплаты. С BrawlBoost не пересекается —
свои таблицы (`Kp*`), свои маршруты (`/kp`, `/api/kp`), своя авторизация.

## Что умеет

- Регистрация и вход (email + пароль, bcrypt, подписанная HMAC-кука).
- Генерация КП по брифу: задача, решение, состав работ, этапы, таблица
  стоимости с тремя вариантами, преимущества, следующий шаг.
- Редактирование текста, перегенерация (Pro и выше), удаление.
- Экспорт: копирование, скачивание `.md`, печать в PDF (`@media print`).
- Тарифы Free / Pro / Business с лимитом КП в расчётном периоде.
- Оплата через абстракцию платёжного провайдера, подтверждение — подписанным
  вебхуком. Отмена подписки с сохранением доступа до конца периода.

## Маршруты

| Страница | Назначение |
| --- | --- |
| `/kp` | Лендинг и тарифы |
| `/kp/login` | Вход и регистрация (`?mode=register`) |
| `/kp/app` | Список КП, счётчик лимита, поиск |
| `/kp/app/new` | Бриф и генерация |
| `/kp/app/p/[id]` | Просмотр, правка, экспорт |
| `/kp/app/billing` | Тариф, оплата, история платежей |
| `/kp/checkout/[ref]` | Страница оплаты mock-провайдера |

API — под `/api/kp`: `auth`, `account`, `proposals`, `proposals/[id]`,
`proposals/[id]/regenerate`, `billing`, `billing/checkout`, `billing/cancel`,
`billing/webhook`, `billing/mock/[ref]`, `checkout/[ref]`.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | да | SQLite-база (общая с BrawlBoost) |
| `KP_SESSION_SECRET` | в проде — да | Ключ подписи сессионной куки. Без него в продакшене вход не работает; в dev подставляется временный |
| `KP_WEBHOOK_SECRET` | в проде — да | Ключ проверки подписи вебхука об оплате |
| `KP_PAYMENTS_PROVIDER` | нет | `mock` по умолчанию. Другое значение — ошибка, пока не добавлен адаптер |
| `ANTHROPIC_API_KEY` | нет | Если задан — текст пишет Claude; иначе используется встроенный шаблонный сборщик |

После изменения схемы: `bun run db:push`.

## Генерация текста

`src/lib/kp/generator/index.ts` выбирает движок:

- ключ Anthropic задан → `llm.ts`, модель `claude-opus-5`;
- ключа нет или запрос упал → `template.ts`, детерминированный сборщик.

Шаблонный путь — не заглушка: он собирает полноценное КП со всеми блоками и
таблицами, поэтому продукт остаётся рабочим без внешних зависимостей. Движок,
которым собрано конкретное КП, сохраняется в поле `engine` и виден в списке.

## Платежи

Приложение общается с платёжкой только через интерфейс `PaymentProvider`
(`src/lib/kp/billing/provider.ts`). Сейчас реализован `mockProvider`: он создаёт
платёж в статусе `pending` и отдаёт ссылку на внутреннюю страницу, которая
имитирует эквайринг. Нажатие «оплатить» не меняет подписку напрямую —
формируется подписанное событие и уходит в тот же обработчик вебхука
(`src/lib/kp/billing/webhook.ts`), который будет принимать события от реального
провайдера.

Обработчик идемпотентен: повторная доставка события не создаёт вторую подписку.

Чтобы подключить Stripe или ЮKassa:

1. Написать адаптер с интерфейсом `PaymentProvider` (создание сессии оплаты).
2. Вернуть его из `getPaymentProvider()` по значению `KP_PAYMENTS_PROVIDER`.
3. В `webhook/route.ts` заменить проверку подписи на проверку провайдера и
   смапить его события в `PaymentEvent`. Остальная логика подписок не меняется.

## Что стоит доделать перед реальными деньгами

- Реальный платёжный адаптер и автопродление подписки (сейчас период разовый,
  на 30 дней).
- Подтверждение email и восстановление пароля.
- Ограничение частоты запросов на `/api/kp/auth` и генерацию.
