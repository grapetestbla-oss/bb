# partner-bot — заявки на статус медиа-партнёра

Телеграм-бот, который принимает анкеты от блогеров и отдаёт их модераторам:
человек заполняет форму в личке, карточка падает в приватную группу с кнопками
«Принять» / «Отклонить», решение автоматически уходит заявителю.

## Как это выглядит

```
Пользователь                     Бот                         Админ-чат
 /start ──────────────────────▶  приветствие + кнопка
 «Подать заявку» ─────────────▶  7 вопросов по одному
 ответы ──────────────────────▶  проверка каждого ответа
                                 предпросмотр карточки
 «Отправить» ─────────────────▶  сохранение в SQLite  ─────▶  карточка + кнопки
 уведомление о решении  ◀──────  запись решения       ◀─────  «Принять»/«Отклонить»
```

## Анкета

| Поле | Проверка |
|---|---|
| Ник в игре | 2–32 символа, буквы/цифры/`_`/`.`/`-` |
| Игровой ID | только цифры, больше нуля |
| Площадка | кнопки YouTube / Twitch / TikTok / Telegram / Другое |
| Ссылка на канал | URL; `@username` разворачивается в `https://t.me/...` |
| Подписчиков | `12000`, `12 000`, `12.5k`, `1,2м` |
| Средние просмотры | то же |
| О себе | необязательно, `-` пропускает |

Заявки с аудиторией меньше `application.min_subscribers` (по умолчанию 1000)
отклоняются сразу на этом шаге — человек не тратит время на остальные вопросы.

## Защита от спама

- одна открытая заявка на пользователя;
- после отказа новая заявка — через `reject_cooldown_hours` (по умолчанию 24 ч);
- одобренную заявку повторно подать нельзя (`allow_resubmit_after_approve`);
- решение фиксируется атомарно: если два модератора нажали кнопки одновременно,
  сработает только первый, второй увидит «Заявку уже закрыли»;
- пользовательский текст экранируется — HTML из анкеты не попадёт в карточку.

## Установка на VPS

```bash
BOT_TOKEN='123456:AA...' ADMIN_CHAT_ID='-1001234567890' ADMIN_USER_IDS='42,77' \
  bash install.sh
```

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `ADMIN_CHAT_ID` — id приватной группы модерации (добавьте туда бота);
- `ADMIN_USER_IDS` — кто вправе решать; если не задать, решает любой участник
  админ-чата.

Токен пишется в `/etc/partner-bot.env` с правами 640 и не попадает в
`config.json`. Сервис ставится под systemd:

```bash
systemctl status partner-bot
journalctl -u partner-bot -f
```

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | приветствие и кнопка подачи |
| `/cancel` | все | прервать заполнение |
| `/pending` | админы | список открытых заявок |
| `/stats` | админы | счётчики по статусам |

## Настройка

`config.json` накладывается на умолчания из `partner_bot/config.py`, поэтому
достаточно указать только то, что меняете.

```jsonc
{
  "application": {
    "min_subscribers": 1000,        // порог аудитории
    "reject_cooldown_hours": 24,    // пауза после отказа
    "max_field_length": 400,        // потолок длины свободных полей
    "allow_resubmit_after_approve": false
  }
}
```

Токен и id админ-чата можно задать переменными `PARTNER_BOT_TOKEN` и
`PARTNER_BOT_ADMIN_CHAT_ID` — они важнее файла.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python tests/test_form.py
.venv/bin/python tests/test_storage.py
.venv/bin/python tests/test_handlers.py
```

Тесты не ходят в сеть: `test_form` проверяет разбор ответов, `test_storage` —
правила повторной подачи и атомарность решения, `test_handlers` собирает роутер
и клавиатуры, то есть ловит опечатки в API aiogram до запуска.

Локальный запуск:

```bash
PARTNER_BOT_TOKEN='123:ABC' PARTNER_BOT_ADMIN_CHAT_ID='-100...' \
  .venv/bin/python -m partner_bot --config config.json
```

## Структура

| Файл | Назначение |
|---|---|
| `partner_bot/form.py` | вопросы и проверка ответов — чистые функции |
| `partner_bot/storage.py` | SQLite: заявки, решения, правила повторной подачи |
| `partner_bot/handlers.py` | диалог и модерация (aiogram) |
| `partner_bot/config.py` | умолчания и валидация конфигурации |
